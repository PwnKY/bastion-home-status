# 状态摘要的性能边界

状态 API 首次打开必须读取真实 current，不用演示、旧绿灯或加大浏览器超时掩盖慢查询。前端仍 10 秒轮询、8 秒超时；后端配置中的 CPU/内存限额不因修复而提高。

## 查询与缓存

- 历史仍为独立 24h/7d 半小时端点，48/336 点，不是全时段 SLA。
- 添加两个兼容旧库的索引：`samples(service,observed,received)`、`receipts(agent,kind,received)`；不改列、不删历史，旧二进制可以忽略新索引。
- 每个窗口用索引找最后一条样本，不解码窗口间全部样本；保留两天 carry-in、最早 75000 条输入上限及接收/插入顺序。不回退到更早的成功。
- 每个来源/范围只计算一次心跳端点，批次收据不混入心跳。过期、失联、replay 与未知分母语义保持不变。
- 冷读并发共享一次最多 4 秒的数据库计算。请求取消即停止等待；共享计算可服务其他浏览器，但也有独立总预算。错误不缓存、不退回旧成功。
- 缓存锁不包住计算；上报 ACK 不等待历史缓存锁。并发写入增加 generation，旧计算不得重新发布成有效缓存。
- 2 秒缓存 TTL 从完成起算。响应重新老化来源和观测年龄，独立撤销过期 RTT、路径、连接数、容量测量，保留仅作参考的来源证据。历史时间不续新。

## 回归与负载

`go test ./...` 包括：

- 独立旧扫描算法与索引取样的逐点对照：缺测、过期、replay、未知、相同时间/接收时间、缺失 RTT、输入上限、来源失联。
- 旧数据库新增索引而不丢记录、单连接阻塞时取消、并发写入失效、取消的浏览器、缓存响应时过期与不可变拷贝。
- 60 项 / 8 来源 / 156000 样本 / 64800 收据的 24 次并发冷打开，不能超过浏览器 8 秒预算。

可单独运行生成数据基准：

```sh
go test -run '^$' -bench 'Benchmark(Dense|Growing)Snapshot$' -benchtime=1x -count=1 ./internal/status
```

Growing 为 156 万样本 / 68 万收据，覆盖约九天每 30 秒输入。所有数据、凭据均临时生成，不含真实部署记录。性能数值依赖硬件；CI 的 race 回归、普通基准和正式机器保留原资源限额的私有旧库预检分别记录，不以本地快机器的结果代替生产验收。

本地 Windows 普通基准中，原 Dense 约 1.13 秒；索引版约 0.1 秒，Growing 约 0.35 秒。正式性能必须另行测量。后端或网络真正不可达时仍显示未知，而非声称任何故障下都保证接口成功。
